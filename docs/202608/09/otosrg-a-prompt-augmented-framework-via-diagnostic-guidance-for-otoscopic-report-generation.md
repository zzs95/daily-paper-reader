- **医学报告自动生成的价值**：自动医学报告生成旨在将医学图像转化为具有临床意义的文本描述，可减轻医生负担，为临床诊断提供有效支持。

## 2. 论文提出的方法论

### 2.1 总体架构：两阶段框架 OtosRG
论文提出的是 **OtosRG（Otoscopic Report Generation）** 框架，整体由两个阶段串联组成，核心思想是**先"看细"再"诊明"**——先精确捕捉病变细节，再用诊断结果指导报告成文。

### 2.2 第一阶段：多尺度引导中间报告生成器（Multi-scale Guided Intermediate Report Generator）
- **核心作用**：从耳镜图像中提取细粒度的病变级信息，生成"中间报告"（intermediate report），描述鼓膜的病灶级别发现。
- **关键模块**：
  - **多尺度特征编码**：通过多尺度特征提取，捕获大小不同的病变区域（如穿孔、积液、瘢痕等）；
  - **空间注意力机制**：让模型聚焦于图像中信息量最大的局部区域，增强关键病理特征；
  - 该阶段生成的中间报告是后续报告合成的"事实基础"，确保最终报告中描述的病变发现与实际图像一致。

### 2.3 第二阶段：诊断增强报告生成器（Diagnosis-Enhanced Report Generator）
- **核心作用**：利用诊断结果增强最终报告的临床导向性。
- **关键模块与技术**：
  - **对比分类学习（contrastive classification）**：在视觉特征上引入对比学习，学习更具判别性的诊断表示，提升诊断分类的准确性；
  - **结构化提示构建**：将**预测的诊断类别**与**第一阶段生成的中间发现**整合，构造结构化的提示（structured prompts）；
  - **大语言模型（LLM）驱动**：将该提示输入大语言模型，引导其生成最终的临床报告，实现临床语言的组织、润色与连贯化。

### 2.4 算法/流程的文字描述
1. 输入耳镜图像；
2. 经过多尺度特征提取与空间注意力，生成包含病灶描述的中间报告；
3. 同时，通过对比分类学习对图像进行诊断预测；
4. 将"预测诊断 + 中间报告"构造为结构化提示；
5. 提示输入 LLM，生成最终临床报告；
6. 训练过程中，两阶段联合优化（分类损失与生成损失）。

## 6. 论文的主要结论与发现

1. **性能超越现有方法**：在 OCASD 数据集上，OtosRG 在多种自动评价指标上优于现有报告生成方法。

4. **诊断引导的提示增强可行**：将预测诊断与图像发现整合到 LLM 提示中，可有效弥补大模型在耳镜图像领域专业知识不足的问题。

### 方法层面
- **LLM 的幻觉风险**：最终报告依赖 LLM 生成，即使有结构化提示约束，仍存在言过其实或与图像事实不符的潜在风险；
- **两阶段误差传播**：中间报告的生成质量与诊断分类的准确性会共同影响最终报告——若某一阶段出错，错误可能被下游放大；

- **推理开销**：两阶段加外部 LLM 的推理流程比单阶段端到端模型更重，实际临床部署的时延与成本可能需进一步优化。

## 总结

OtosRG 是首个面向耳镜图像报告生成的诊断引导提示增强框架，通过"多尺度病灶感知 + 诊断对比学习 + LLM 结构化提示"的组合，系统性地解决了耳镜图像病变细微与诊断信息不足的问题。在 OCASD 数据集上取得了优于现有方法的性能，为耳内镜（耳镜）这一细分医学影像领域的自动报告生成提供了有效范式。其核心不足在于仅单一数据集评测、缺乏专家临床评估、以及 LLM 幻觉与部署成本的潜在风险，未来可在多中心数据验证、幻觉抑制与轻量化方向进一步展开。
