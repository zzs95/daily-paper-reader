### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：代码作者归属（Code Authorship Attribution, CAA）是代码风格计量学（Code Stylometry）的核心任务，旨在通过分析编码结构、命名约定、格式风格等特征来识别代码样本的真实作者。CAA 在软件工程中具有广泛价值，包括缺陷分诊（bug triaging）、故障定位（fault localization）、开发者画像与工作负载平衡、安全与合规审计、测试优先级排序等；同时也在网络安全与软件取证（如版权纠纷、抄袭检测、刑事起诉支持）中发挥关键作用。
- **传统方法的瓶颈**：以往的 CAA 技术（基于 ML/DL）主要依赖手工设计的代码特征，存在两大缺陷：(1) 手工特征难以全面刻画多样化的编码风格；(2) 对对抗攻击高度敏感，作者可通过有目的的代码扰动逃避识别。
- **研究契机**：基于 Transformer 的语言模型（LMs）在众多软件工程任务和自然语言作者归属任务中已展现出卓越性能，但其在 CAA 任务上的有效性尚未被充分理解。本文是首个大规模、系统地评估语言模型在 CAA 任务上表现的研究，其核心意义在于：考察 LMs 是否能在多样化场景下胜任作者归属任务、它们究竟学到了什么样的风格特征、以及它们对对抗攻击的鲁棒性如何，从而为未来 CAA 系统的设计提供方向。

### 2. 论文提出的方法论

- **核心思路**：将 CAA 形式化为多分类问题——模型输入代码片段，从已知作者集合中预测其作者。在此基础上，对七个开源代码语言模型进行微调（fine-tuning），并辅以可解释性分析与对抗攻击评估三条主线。
- **模型微调细节**：
  - 七个模型：Code Llama (7B)、DeepSeek-Coder (1.3B)、UniXcoder (223M)、CodeBERT (125M)、ContraBERT_C (125M)、ContraBERT_G (125M)、GraphCodeBERT (125M)。
  - 编码器模型采用 [CLS] token 嵌入加分类层；解码器模型（Code Llama、DeepSeek-Coder）采用最后 token 的嵌入进行分类。
  - 损失函数为交叉熵，优化器为 Adam；最大 20 个 epoch，早停 patience=3；超参数网格搜索（学习率 5e-05/3e-05/2e-05 × batch size 16/32），基于 K 折交叉验证的平均 F1 选优。
  - Code Llama 因 GPU 显存限制采用 LoRA 微调（仅微调 Wq 和 Wv 投影层，rank=32，alpha=64，可训练参数约 1678 万，仅占 0.24%）。
  - 超长代码按模型输入上限切块，最终通过各块得分求和聚合得到整段代码的预测。
- **可解释性方法（RQ2）**：
  - 使用 **Integrated Gradients (IG)** 计算每个 token 对预测的贡献分数，并取 top 30% 重要特征进行分析。
  - 用 **Necessity（必要性）** 和 **Sufficiency（充分性）** 两个指标验证解释的忠实性（faithfulness）。
  - 通过 t-SNE 可视化、词云、特征重叠度分析检验 LMs 是否学到正交（orthogonal）的作者专属风格。
  - 对嵌入空间做分布分析：计算同一作者内（intra-author）与不同作者间（inter-author）的余弦相似度分布，并以 **Jensen-Shannon (JS) 散度** 量化两类分布的分离程度。
- **对抗攻击方法（RQ3）**：
  - 使用 **GPT-4** 按 28 条语义保持的代码变换提示词生成对抗样本，涵盖 8 大类变换：语句变换、命名变换、算子变换、数据变换、循环变换、控制流变换、函数变换、杂项变换（删注释、删无用代码、加打印语句等）。
  - 双重验证流程：① 将对抗样本提交至 LeetCode 平台验证功能正确性（语义保持约束）；② 使用自定义解析器进行三步骤验证（适用性检查、正确性检查、一致性检查，排除 GPT-4 引入的非预期改动）。
  - 另用 ALERT 攻击方法作为灰盒对比基线。

### 3. 实验设计

- **数据集**（共 6 个，涵盖 12,000+ 代码片段、463 位开发者）：
  - 已有数据集：GCJ-CPP（20 作者/160 样本）、GCJ-Java（74/2202）、GCJ-Python（66/660）、GitHub-C（66/1916）、GitHub-Java（39/2667）。
  - **新构建数据集**：LeetCode（198 作者/4753 样本，覆盖 C++、Java、Python、JavaScript、C#、Ruby 六种语言），专为评估多语言、样本不均衡、短代码、低风格变异、对抗攻击等场景而设计。
- **对比基线**：PbNN（Path-based Neural Network，2021 年基于 code2vec 的语言无关 CAA 基线），以及 ALERT 攻击方法（作为灰盒攻击对比）。
- **评测指标**：Accuracy、Precision、Recall、F1-Score；统计显著性采用 Mann-Whitney U 检验（α=0.05）。
- **关键实验设置**：K 折交叉验证（10 折，GCJ-CPP 因每作者仅 8 个样本用 8 折）；所有模型在相同折上训练/测试。
- **人类评估**：对对抗样本的自然度进行人工评估——1 位作者 + 4 位软件工程博士生，抽样 370 个样本（95% 置信水平），从变换遵循度、代码整洁度、人类书写合理性三维度评估，评估者间一致性平均 93.75%。

### 6. 论文的主要结论与发现

- **发现 1（RQ1）**：LMs 全面优于 PbNN，且在 LeetCode 数据集上优势最大（Accuracy 提升超 130%，F1 最高提升 213%）。大模型（DeepSeek-Coder、Code Llama）在多语言、不均衡、短代码、低风格变异数据集上表现更好；小模型（CodeBERT 等）在均衡、单语言数据集上表现优异。
- **发现 2**：LMs 的优势源于预训练嵌入带来的**更强的作者可分性**——DeepSeek-Coder 在 GitHub-Java 和 LeetCode 上的 JS 散度分别为 0.992 和 0.666，而 PbNN 仅 0.924 和 0.181。
- **发现 3**：训练样本量并非决定因素——LeetCode 中 C++ 占比最高（62.19%）但平均准确率仅 64%，C# 仅占 2.01% 却达 94%，原因是 C++ 解法风格趋同、风格变异度低（JS 散度 0.26 vs C# 0.58）。
- **发现 4**：错误归属集中在两类样本——风格高度重叠/算法受限问题的代码（JS 散度仅 0.016，两分布几乎完全重合）以及低于 200 token 的短代码片段（38% 的错误归属归因于此）。
- **发现 5**：不同 LMs 学到**正交且互补**的风格特征（top 30% 重要特征经 Necessity/Sufficiency 验证忠实），Code Llama、CodeBERT 等各自能正确归因其他模型不能的样本，为集成方法提供依据。
- **发现 6**：LMs 整体比 PbNN 更抗对抗攻击——PbNN 对抗成功率最高（42.18%）；但 Code Llama 表现反常（56.57%，可能因 LoRA 部分微调）。
- **发现 7**：鲁棒性取决于**特征利用策略而非模型规模**——小模型（125M）对 14 类 AST token 类别呈分布式注意（distributed attention），大模型和 PbNN 呈集中式注意（concentrated attention，如 PbNN 集中于预处理指令和注释、UniXcoder 集中于标识符），变换只扰动部分类别时分布式模型仍有可依赖的未扰动特征。
- **发现 8**：对比预训练（ContraBERT_C/G 的 InfoNCE 目标）显著提升了对变量重命名、函数重命名、语句重排序等镜像其训练增强的对抗攻击的鲁棒性。
- **发现 9**：修改 token 数量越多的变换越有效——循环变换、函数变换、杂项变换（删注释/删无用代码/加打印语句）是攻击成功率最高的规则。

### 7. 优点

- **研究空白填补**：首次对 LMs 在 CAA 任务上做大规模系统性评估，覆盖多架构、多规模、多预训练策略的模型矩阵。
- **数据集贡献**：构建了新颖的 LeetCode 多语言数据集，专门挑战短代码、不均衡分布、低风格变异和对抗攻击测试场景，且可通过平台提交验证语义保持性。
- **严谨的对抗攻击流程**：28 种变换规则 + 功能验证（LeetCode 提交）+ 三步骤解析器验证 + 人类自然度评估，多层过滤保证对抗样本质量；且与 ALERT 灰盒攻击做了对比，明确区分了黑盒与灰盒威胁模型的差异。
- **可解释性分析深度高**：IG 归因 + Necessity/Sufficiency 忠实性验证 + t-SNE/词云定性分析 + 嵌入空间 JS 散度定量分析 + 14 类 AST 类别归因的机制分析，多角度解释模型行为。
- **发现具有实践指导意义**：如长短代码的可靠性边界（约 200 token）、特征利用策略与鲁棒性的关系、对比预训练的价值、集成模型与知识蒸馏的可行方向等，对未来 CAA 系统设计有直接参考价值。
- **开放科学**：提供了完整的在线附录与代码仓库以支持复现。
