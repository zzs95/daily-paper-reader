## 论文核心问题与整体含义

### 研究动机与背景

- **背景**：扩散语言模型（dLLM）通过迭代去噪过程定义文本分布，是自回归（AR）语言模型之外的一种新范式。尽管近期 dLLM 已在多项任务上接近强 AR 模型，但关于其扩展行为的研究仍主要集中于稠密架构（dense architectures）。
- **核心问题**：混合专家（MoE）dLLM 的缩放行为——包括优化超参数、计算分配（模型规模 vs. 训练数据）以及 MoE 架构设计——是否遵循与 AR MoE 模型相同的规律，此前尚不明确。
- **关键动机**：现有 MoE dLLM（如 LLaDA MoE 7B-A1B）的设计主要继承 AR MoE 的实践，但 dLLM 与 AR 模型在训练目标上有本质差异：dLLM 优化的是掩码去噪目标，监督信号仅落在被掩码的位置，且每个预测都基于被破坏的序列（随噪声水平变化）而非因果前缀。因此，AR 经验不能直接迁移，需要 dLLM 专属的缩放校准。
- **整体含义**：这项工作填补了 MoE dLLM 缩放规律研究的空白，建立了面向优化、计算分配和专家架构的实用缩放定律与设计原则，并通过大规模训练验证了这些原则的实际价值。

## 方法论

### 核心思想

论文采用"小规模测量 → 拟合幂律缩放定律 → 外推到大模型训练"的经典缩放研究范式，但针对 MoE dLLM 的特点进行了专属校准。研究分三个阶段推进：

1. **优化超参数缩放**：校准随训练计算量（FLOPs）变化的最优批大小（batch size）和学习率。
2. **计算分配缩放**：通过 IsoFLOP 分析确定固定计算预算下，激活模型侧计算（每 token FLOPs）与训练 token 数之间的最优分配。
3. **MoE 架构缩放**：在固定激活模型侧预算下，分解激活预算为**激活比例 A**、**专家粒度 G** 和**共享专家比例 S** 三个维度，逐一扫描其最优配置。

### 关键技术细节

#### 1. 优化超参数缩放（对数幂律拟合）

- 在 158M、1B、3.6B 三个模型尺度上，对计算预算 \(10^{18} \sim 3\times10^{20}\) FLOPs 进行联合搜索，拟合得到：

\[
B^* = 0.374\cdot C^{0.3481},\quad \eta^* = 64.8\cdot C^{-0.2447}
\]

- 其中 \(B^*\) 为最优名义 token 批大小，\(\eta^*\) 为最优学习率，\(C\) 为训练 FLOPs。
- 与 DeepSeek LLM 的 AR 缩放定律（\(B^*\propto C^{0.3271}\), \(\eta^*\propto C^{-0.1250}\)）相比，dLLM 的批大小增长更快、学习率衰减更快。
- **解释**：dLLM 每次更新只监督被掩码的位置（均匀时间步采样下期望仅一半 token 被预测），名义批大小与有效监督目标数不对应，导致梯度噪声特性不同。

#### 2. 计算分配缩放（IsoFLOP 分析）

- 定义 \(C = M\cdot D\)，其中 \(M\) 为每 token 激活非嵌入 FLOPs，\(D\) 为训练 token 数。
- 在 \(10^{17} \sim 10^{20}\) FLOPs 的固定预算下，扫描不同模型规模与数据量的分配组合，拟合最优分配前沿：

\[
M^*(C) = 0.5152\cdot C^{0.475},\quad D^*(C) = 1.9411\cdot C^{0.525}
\]

- **发现**：模型侧指数 0.475 小于数据侧指数 0.525，即最优 token 预算增速快于激活模型侧计算——呈"轻微数据侧倾斜"。
- 与已有缩放规律对比：稠密 dLLM 前沿（如 SMDM、Quokka、DLMs）均呈模型侧主导；而 MoE dLLM 前沿更偏向数据。这与"稀疏激活"和"扩散建模"各自单独推动数据侧倾斜的趋势一致。

#### 3. MoE 架构缩放（三维扫描）

- 在五个参考计算预算（\(6\times10^{17} \sim 6\times10^{19}\) FLOPs）下，固定 \(M^*(C)\) 逐一扫描三个架构维度：
  - **激活比例 A**：越低越好，且随规模增大收益越明显；但最小预算下最稀疏配置并非最优（过于稀疏的专家池需要足够算力才能被有效优化）。
  - **专家粒度 G**：无明显单调趋势，\(G = 8 \sim 16\) 在所有尺度上均稳健，说明粒度不是主要缩放方向。
  - **共享专家比例 S**：在所有尺度上 \(S = 33.3\%\) 最优（U 型曲线的最低点），与 AR MoE 的常见做法（如 DeepSeekMoE 的 25%、Qwen3 的 0%）存在显著差异。

### 大规模模型设计

基于上述缩放定律，设计 **LLaDA MoE v2 30B-A3B**：

- 总参数量 30B，每 token 激活 3B 参数。
- 架构配置：\((A, G, S) = (9.09\%, 8, 33.3\%)\)，即 128 个路由专家、top-8 路由、1 个宽度为 4 倍专家宽度的共享专家。
- 训练策略：五阶段预训练（10T + 10T + 2T 退火 + 500B 上下文扩展 + 1T 长上下文退火），共 23.5T token；上下文长度从 4K 扩展到 32K，RoPE 基数从 10,000 提升至 500,000。
- SFT：7M 指令-响应对，仅对响应部分应用掩码去噪，不采用 RL。

## 主要结论与发现

1. **优化超参数**：MoE dLLM 的最优批大小随算力增长更快（指数 0.3481 vs. AR 的 0.3271），学习率衰减更快（指数 −0.2447 vs. AR 的 −0.1250）。AR 缩放规律是有效先验，但需 dLLM 专属校准。
2. **计算分配**：MoE dLLM 的最优分配近平衡但偏向数据侧——token 预算增速（0.525）快于激活模型侧计算增速（0.475），与稠密 dLLM 的模型侧主导趋势不同。
3. **MoE 架构**：
   - 更大规模偏好更稀疏的激活（更低的激活比例 A）；
   - 专家粒度 \(G=8\sim16\) 在所有尺度上稳健，不是主要缩放方向；
   - 共享专家比例 \(S=33.3\%\) 在所有尺度上最优，与 AR MoE 的"固定一个共享专家"规则明显不同。
4. **大规模验证**：
   - LLaDA MoE v2 仅用 Qwen3 约 65% 的预训练 token 即逼近 Qwen3 在若干知识、推理和编程基准上的表现；
   - 比 SDAR Sci 平均高 3.78 分（58.60 vs. 54.82），编程任务差距尤为显著（HumanEval +16.46，BigCodeBench +7.98）；
   - 仅用约 50% 的训练 FLOPs 即超越此前无缩放定律指导的 LLaDA MoE 7B-A1B；
   - SFT（无 RL）后，在 8 个推理与编程基准中 7 个超过 SDAR Chat，并在 AIME 24/25、MBPP、LiveCodeBench 上接近 Qwen3，MultiPL-E 超过 Qwen3。

## 优点

1. **系统性与完整性**：首次系统刻画了 MoE dLLM 在优化、计算分配、架构三个维度上的缩放行为，并给出了定量幂律拟合。
2. **清晰的对照分析**：通过 Ling（AR 稠密 vs. AR MoE）和 SMDM（AR 稠密 vs. Diffusion 稠密）两组配对比较，巧妙分离了"稀疏激活"和"扩散建模"对数据侧倾斜的各自贡献，使结论更有说服力。
3. **闭环验证**：从小规模缩放实验推导出设计原则，再将其应用于大规模模型训练，并用下游基准验证效果——形成了完整的"定律→设计→验证"闭环。
4. **训练效率显著**：LLaDA MoE v2 从零训练仅用 23.5T token 即在多项任务上接近 Qwen3（36T），大幅降低了预训练成本，体现了缩放定律指导的实际价值。
5. **SFT 有效性**：仅用标准 SFT（无 RL）就构建出强指令模型，为进一步整合 RL 留下了空间，也说明预训练质量对下游能力的决定性作用。
6. **工程细节完整**：附录提供了完整的计算量核算公式、MoE 实现细节（路由、共享专家缩放因子 λ 的推导）、各扫描配置表，可复现性较强。

## 不足与局限

1. **维度间交互未刻画**：论文明确承认各缩放维度是独立扫描的，未考虑优化超参数、计算分配和架构维度之间的交互效应。真实最优配置可能偏离各维度独立最优的组合。
2. **最小规模异常未深入解释**：在最小计算预算下，最稀疏激活比例并非最优（次稀疏反而更好），论文仅给出直觉性解释（专家池过大需足够算力优化），缺乏理论或更细粒度实验论证。
3. **大规模实验仅验证单一配置**：大规模训练只报告了一个配置（30B-A3B, 23.5T tokens），没有在不同规模上重复验证缩放定律的普适性，也未提供随机种子消融等统计稳健性分析。
4. **计算分配实验基于超参数定律外推**：IsoFLOP 扫描中使用的批大小和学习率来自拟合的超参数定律，拟合误差可能沿链式传播影响计算分配结论。
5. **基准覆盖有限**：虽然覆盖了知识、推理、编程，但未涉及多语言任务、长上下文理解、指令跟随多样性、安全性评估等维度，对模型能力的刻画不够全面。
6. **RL 缺失**：SFT 后未使用 RL，与带 RL 的 Qwen3、SDAR Chat 对比时在部分任务（如 MATH、LiveCodeBench）仍有明显差距，RL 的增益尚未被验证。
7. **共享专家比例的 dLLM 特异性**：论文发现 \(S=33.3\%\) 最优，但未深入探讨为什么 dLLM 需要比 AR 模型更高的共享专家比例——这与掩码去噪目标中 router 输入状态不稳定的机制性联系尚未建立。
8. **算力消耗未做详细分解**：尽管报告了总 GPU 小时数，但未提供不同训练阶段的算力分配和效率分析，难以评估各阶段配置的性价比。
