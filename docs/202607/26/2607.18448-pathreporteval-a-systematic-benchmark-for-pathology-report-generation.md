病理报告生成（从全切片图像生成诊断性文本）是一个快速发展的多模态学习任务。然而，当前研究面临两大障碍：  
- **实验不可比**：不同工作使用异构的数据集、预处理流程、视觉编码器、模型实现、解码策略和评估协议，无法直接比较。

因此，论文旨在建立一个**标准化的基准和评估框架**，实现跨方法、跨数据集、跨编码器的公平比较，并引入一个**临床导向的评估指标**来弥补传统指标的不足。

# 2. 论文提出的方法论

## 2.1 核心思想
提出一个**模块化、可扩展的基准框架 PathReportEval**，统一数据预处理、特征提取、训练、解码和评估全流程，并设计**临床报告质量分数（CRQS）**，将报告转化为结构化临床属性，从四个维度评价临床保真度。

## 2.2 关键技术细节

### 标准化实验流水线
- 使用 **TRIDENT** 工具对WSI进行组织分割、补丁提取（20×放大倍率，补丁大小因编码器而异）。
- 所有方法统一使用相同的分词器、训练超参数、解码策略。
- 基于PyTorch Lightning实现，保证实现一致性。

### CRQS（Clinical Report Quality Score）

CRQS通过结构化提取函数 \( E(R) = \{(f_i, v_i)\}_{i=1}^n \) 将参考报告和生成报告映射到预定义的临床属性字段（如诊断、分级、分期、边缘状态等）。关键字段集合 \( K \) 强调可视觉推断的、高临床影响的属性。

四个子分数：
- **临床事实覆盖率（CFC）**：参考事实中被正确恢复的比例。
- **关键信息召回率（KIR）**：关键字段中被正确恢复的比例。
- **幻觉率（HR）**：生成事实中不被参考支持的比例。
- **临床不一致分数（CDS）**：双方都含有的字段中值矛盾的比例。

综合分数：
\[
\text{CRQS\_raw} = 0.3\cdot\text{CFC} + 0.4\cdot\text{KIR} - 0.2\cdot\text{HR} - 0.4\cdot\text{CDS}
\]
归一化到 \([0,1]\)：\( \text{CRQS} = \text{CRQS\_raw} / 0.7 \)。

权重设计强调关键信息召回，重罚矛盾（因为矛盾比幻觉更危险）。

## 2.3 算法流程（文字说明）
1. 输入：全切片图像，参考报告。
2. 特征提取：TRIDENT流水线 → 编码器（CONCHv1.5/UNI2-h/H-Optimus-1）→ 补丁级特征。
3. 报告生成模型：各方法（WSI-Caption, HistGen, BiGen, SCOUT）处理特征生成文本。
4. 评估：分别计算传统NLG指标和CRQS。CRQS使用LLM将报告解析为结构化字段，经病理专家验证，然后计算四个子分数并合成总分。

# 3. 实验设计

## 3.1 数据集
三个具有互补特性的公共数据集：

| 数据集 | 样本量 | 多样性 | 报告同质性 | 注释噪声 | 特点 |
|--------|--------|--------|------------|----------|------|
| TCGA (PathText) | 7074/884/885 | 低 | 中等 | 高 | 报告较长且不一致，噪声高 |
| HistAI | 9980/1248/1248 | 高 | 中等 | 中等 | 多机构，多样性强 |
| REG 2025 | 5924/740/741 | 高 | 高 | 低 | 短而半结构化报告，一致性高 |

所有方法使用相同的固定训练/验证/测试划分。

## 3.2 基准方法
四种代表性报告生成方法：
- **WSI-Caption (MI-Gen)**：基于多实例生成模型
- **HistGen**：层次局部-全局编码 + 跨模态上下文交互
- **BiGen**：检索增强，引入外部文本知识
- **SCOUT**：上下文感知多模态 Transformer + 概念条件特征精炼

## 3.3 视觉编码器
三种病理预训练编码器：
- CONCHv1.5
- UNI2-h
- H-Optimus-1

## 3.4 对比设置
共 4 种方法 × 3 种编码器 × 3 个数据集 = 36 个模型配置（每个配置在相同实验条件下训练和评估）。结果按方法平均和按编码器平均给出。

## 3.5 评估指标
- 传统NLG指标：BLEU-1~4、ROUGE-L、METEOR
- 临床指标：CRQS（及四个子分数）

# 6. 论文的主要结论与发现

1. **传统NLG指标与临床正确性弱对齐**：模型在BLEU/ROUGE/METEOR上相似，但CRQS可能差异显著，说明词汇相似度无法反映临床错误。
2. **CRQS能揭示传统指标掩盖的失败模式**：例如，TCGA上高幻觉率（HR≈0.5）降低了CRQS，但NLG指标可能给出“良好”分数。
3. **数据集结构显著影响性能**：REG（短且结构化的报告）上所有指标更高，CRQS与NLG一致性较好；TCGA（长而自由文本）上CRQS低、NLG指标相对高，表明临床保真度差。
4. **编码器影响具有数据集依赖性**：无明显占优编码器，UNI2-h在REG上表现最好，H-Optimus-1在HistAI上更好，CONCHv1.5在某些TCGA子任务中较好。
5. **方法间差异在CRQS下更明显**：例如在HistAI上，BiGen的CRQS最高（0.2938），而SCOUT的BLEU-1最高（0.3143），说明方法选择与评估指标相关。
6. **公开框架和标准化协议能够提升基线表现**：部分方法在统一实验下取得了比原论文更好的结果，表明预处理和训练一致性对性能有实质影响。

# 7. 优点

- **标准化程度高**：统一了预处理、特征提取、训练、解码、评估全流程，消除实现差异，提供固定数据划分和开源代码，促进可重复性。
- **临床导向评估**：CRQS从四个维度捕捉临床重要错误（遗漏、关键信息缺失、幻觉、矛盾），比传统指标更具诊断相关性，且分解成可解释的子分数便于错误分析。
- **覆盖范围广**：横跨三个代表性数据集、四种不同架构的方法、三种视觉编码器，系统评估了多种因素对报告质量的影响。
- **模块化设计**：框架支持插件式扩展，允许新方法、新数据集、新编码器轻松接入。
- **消歧逻辑**：CRQS考虑了临床等价表述（同义词解析、否定处理、值标准化），避免因措辞不同而错误惩罚。
- **定性示例**：展示了METEOR高分但临床错误（CIN2误判为CIN1）和METEOR低分但临床正确（不同措辞描述良性）的对比，直观说明问题。

# 8. 不足与局限

- **CRQS依赖结构化提取**：使用LLM管道从自由文本中提取字段，可能引入解析误差或不一致，尽管经过病理专家验证，但对复杂病例或罕见字段的鲁棒性未充分分析。
- **临床字段集预定义**：当前只包含常见属性，可能遗漏细微描述或罕见病理特征，且对不同癌种的特异性可能不足。
- **权重设定主观**：CRQS的权重（0.3,0.4,0.2,0.4）基于作者判断，未进行敏感性分析或与专家偏好校准。
- **缺乏人工评估**：没有与病理医生对生成报告的整体临床评分数值对比来验证CRQS的有效性（仅提供定性示例）。
- **消融实验不完整**：未分析解码策略、报告长度、不同LLM提取器的影响，也未对比CRQS与已有事实基指标（如FACTent）。
- **算力细节缺失**：未报告训练时长、能耗或具体经济成本，影响复现和可扩展性评估。
- **通用性风险**：所有实验仅限三个公开数据集，可能无法代表真实临床场景的多样性和噪声水平；合成或低质量数据的表现未知。
- **伦理声明**：论文在附录中简要讨论了临床应用风险（错误报告可能造成严重后果），但未深入探讨偏见、公平性等社会影响。
