## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：当前医疗大语言模型（Medical LLM）的评估通常仅依赖诊断准确率（如是否选对最终诊断），但这种单一指标无法揭示模型是否恰当使用了病例中的临床证据。例如，模型可能因为过度依赖无关线索（如“无近期旅行史”来判断过敏性鼻炎）、忽略关键阳性体征或错误关联局部症状而“碰巧”选对答案。
- **背景含义**：临床证据具有诊断相对性——同一症状对不同疾病可能起支持、竞争或排除作用。准确率将所有这些差别压缩为一个最终标签，无法区分模型行为是源于合理的鉴别诊断还是证据误用。因此，作者提出一种行为审计方法，系统检查LLM在控制证据输入下的诊断偏好变化，为高风险的临床AI应用提供更细粒度的可靠性评估。

## 2. 方法论

### 核心思想
- 将临床病例分解为多个**证据单元**（如症状、体征、阴性发现、病史等），在控制哪些证据可见的情况下，反复向模型提问并要求从候选诊断中选择，记录每个诊断的**边际分数**（margin）。然后通过**低阶交互挖掘**（low-order interaction mining）找出多个证据联合时对诊断边际产生的超出独立效应的贡献，并结合**诊断相对的角色框架**（diagnosis-relative evidence roles）区分合理交互与候选失败。

### 关键技术细节
1. **诊断评分与边际定义**  
   对于每个病例，证据集合 \(E=\{e_1,...,e_n\}\)，候选诊断 \(C=\{c_1,...,c_m\}\)。在某个证据子集 \(T \subseteq E\) 下，模型对诊断 \(d\) 的边际分数为：  
   \[
   v_d(T) = s_T(d) - \max_{c_j \in C, c_j \neq d} s_T(c_j)
   \]  
   其中 \(s_T(d)\) 是模型对选项字母的下一 token 对数概率。

2. **交互效应计算**  
   对于非空集合 \(S \subseteq E\)，交互效应定义为：  
   \[
   I_d(S) = \sum_{T \subseteq S} (-1)^{|S|-|T|} v_d(T)
   \]  
   正值为增加诊断 \(d\) 的边际，负值为降低或偏向竞争者。论文主要关注低阶交互（\(|S| \leq 3\)），因其可解释且计算可行。

3. **诊断相对的角色分配**  
   每个证据单元相对于审计的诊断 \(d\) 被赋予角色：支持性证据、竞争者支持证据、排除/阴性证据、背景/风险证据、不相关/局部证据。这些角色是方向性期望，用于解释交互符号和强度，而非自动判定错误。

4. **从交互到审计标签**  
   自动标签分为两大类：
   - **合理机制**：忠实目标支持、差分冲突/取消、冗余、背景/历史影响。
   - **候选失败机制**：否定/缺失证据误用、无关证据误用。这些候选需经过稳定性检查（提示措辞、选项顺序、扰动语义）和临床评审后才能确认为无效。

### 算法流程（文字描述）
1. 输入临床病例，提取证据单元集合 \(E\) 和候选诊断集合 \(C\)。
2. 枚举所有目标子集 \(T\)（低阶组合），对每个 \(T\) 用固定模板提示模型，获取所有候选诊断的对数概率。
3. 对每个诊断 \(d\) 计算边际 \(v_d(T)\)。
4. 对每个非空集合 \(S\)（\(|S| \leq 3\)）计算交互效应 \(I_d(S)\)。
5. 按强度排序 \(|I_d(S)|\)，分配诊断相对角色，应用自动标签规则。
6. 对候选失败机制进行稳定性过滤（提示词、选项顺序、删除vs中和），再进行临床评审，最终确认无效机制。

## 3. 实验设计

### 数据集
- **DDXPlus**：结构化患者发现与鉴别诊断列表，500例验证集，每例8个审计证据单元。
- **CupCase**：病例报告风格描述，200例，每例6个审计单元。
- **MedCase**：较长病例叙述，200例，每例6个审计单元。

### Benchmark
- 基准指标：**全证据诊断准确率**（full-evidence accuracy），作为传统评估对比。
- 审计指标：交互强度分布、机制占比、临床评审确认的无效率。

### 对比方法
- 五个**开源指令微调LLM**：Qwen2.5-7B-Instruct、OpenBioLLM-8B、MedGemma-4B、BioMistral-7B、Llama3-Med42-8B。
- 消融实验：比较**单证据**（leave-one-out）、**两两交互**与**三阶交互**在识别可疑交互和确认无效机制上的覆盖能力。
- 鲁棒性检查：不同提示措辞（clinical-summary vs. questionnaire）、不同选项顺序、删除vs中和扰动（将隐藏证据替换为“not specified”）。
- **临床评审**：5位医学博士独立盲审130个高强度交互，计算Fleiss' κ=0.82，77%完全一致。

## 5. 主要结论与发现

1. **准确率不代表证据使用保真度**：模型间准确率排序与忠实目标证据强度排序不一致，高准确率模型可能仍存在大量冲突/取消交互或候选失败。
2. **多数交互是合理的**：忠实目标支持和差分冲突/取消占DDXPlus交互强度的88.5%（CupCase 100%，MedCase 100%），表明大量证据交互在临床上合理，而非失败。
3. **无效机制集中在证据极性与特异性**：在DDXPlus的130个评审样本中，11个确认为无效或捷径式，主要特征为否定/缺失证据（如“无近期旅行史”支持过敏性鼻炎）和临床局部证据（如皮疹/脱皮支持腹股沟疝）。
4. **稳定性过滤是关键**：从300个原始可疑交互，经提示词、选项顺序、中和扰动过滤后，剩下120个高质量候选，精度从0.55提升到0.80，假阳性从0.20降到0.08。
5. **反事实验证区分局部伪影与全局依赖**：例如皮肤证据对腹股沟疝是局部不连贯而非全局依赖，而疾病名称家族史会明显放大置信度且可能改变top-1诊断。

## 6. 优点

- **行为审计而非内省**：不依赖模型生成的推理链或注意力权重，只根据控制输入下的输出变化来推断证据使用，避免了解释忠实性问题。
- **诊断相对的角色框架**：承认同一证据对不同诊断意义不同，避免将负交互或局部支持一律视为错误，更符合临床现实。
- **鲁棒性过滤与临床审核相结合**：自动标签仅作为筛选信号，最终失败判断需通过稳定性检查（提示词、顺序、扰动）和医学专家盲审，提高了结论可信度。
- **消融实验揭示了低阶交互的必要性**：单证据或两两交互无法覆盖大部分无效机制，三阶交互才能有效捕获；这一发现有方法论价值。
- **跨数据集验证**：在DDXPlus、CupCase、MedCase三种不同结构的数据上观察到一致的机制分布，表明审计框架具有一定通用性。

## 7. 不足与局限

- **模型范围有限**：仅评估了5个开源模型（最大8B参数量），未涉及GPT-4、Claude、Med-PaLM等闭源或更大模型，结论普遍性受限。
- **实验覆盖局限**：DDXPlus的临床评审样本是富集采样，不能作为总体错误率的无偏估计；计算资源未披露。
- **依赖证据单元与角色注释**：审计结果高度依赖于如何定义证据单元和分配角色，DDXPlus支持结构化角色，但CupCase/MedCase依赖提取的句子，可能遗漏或错误归类。角色分配本身也引入主观性。
- **选项分数偏差**：使用选项字母的对数概率，可能受token先验和位置影响；虽然做了顺序鲁棒性检查，但未完全校准为诊断概率。
- **仅适用于多项选择格式**：当前审计要求固定候选诊断列表，对于开放式诊断任务（如生成式）不直接适用。
- **未考虑推理链**：论文明确不评估模型内部推理过程，但这也意味着无法区分是模型缺乏医学知识还是证据使用算法问题，只能观察到行为模式。
